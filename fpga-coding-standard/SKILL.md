# FPGA (Verilog) 编码规范

## 触发条件
当用户请求编写、修改、审查任何 `.v` 或 `.sv` 文件，或讨论 Vivado 综合、仿真相关问题时，自动应用本技能。

## 核心约束
1. **文件格式**：遵循当前 Trae 编辑器的全局配置（UTF-8 无 BOM，LF 换行，4 空格缩进）。
2. **命名与端口**：信号使用小写加下划线（如 `data_valid`）。模块例化**必须按名字关联**（如 `.clk(clk)`）。
3. **组合逻辑安全**：使用 `always @(*)`，所有分支必须覆盖（禁止推断出 Latch），`case` 必须有 `default`。禁止使用魔法数字，必须用 `parameter` / `localparam`。
4. **时序与复位**：时序逻辑必须用非阻塞 `<=`，组合逻辑用阻塞 `=`。**严禁使用内部逻辑生成的信号作为时钟**。复位必须明确同步/异步方式，且寄存器复位必须赋初值。
5. **算术与运算符**：严禁在 `if` 条件或算术运算中直接使用 `/` 和 `%`（会消耗巨大资源）。注意 `signed` 与无符号数混用风险。内部逻辑严禁使用 `'z'`（高阻态只能在顶层 `inout` 使用）。

## 注释规范（严禁废话）
- 绝不要给 `clk`、`rst_n` 或基础端口加废话注释。
- 只给复杂逻辑、状态机含义或特殊修改解释**“为什么”**。
- 保留我原有的关键注释，单行注释请用 `//`。

## 🚨 强制代码自检流程（AI 必做）
修改代码后，必须进行以下自检，并在回复末尾输出报告：

1. **位宽闭环**：检查加减乘运算的位宽是否防溢出，赋值左右两边位宽是否匹配，新增变量是否已声明类型。
2. **模块联动**：若修改了子模块端口，必须检查顶层例化是否同步更新。
3. **结构安全**：检查是否混用阻塞/非阻塞赋值，是否有多驱动，状态机是否为规范的三段式。

## 输出要求
- 当前开发环境已配置 Trae 编辑器，并强制启用了 `utf8` 和 `\n` 格式。
- **不需要**在回复末尾附加关于文件编码的警告或提醒，直接生成代码即可。
- 回复末尾仅需输出以下自检报告：
  ✅ **位宽检查**：[通过 / 发现并修复了隐患]
  ✅ **结构检查**：[通过 / 发现并修复了隐患]
  ✅ **注释检查**：[已确认无废话注释]
